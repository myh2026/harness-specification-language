沙盒全链路装机实测（bun 跑 dhv-ts + cargo 构建 dhv + 双编译器 conformance 对拍）驱动的一致性/健壮性修复。全部用例先复现后修复，回归锁定在 `tests/hsl/run-all.ts` v0.2.62 批次与 `dhv/tests/fixtures/parse/`。

## Checklist

- [x] **G-8 expr 守卫指纹**（checker.ts）：Span 是 `{line,col,file}` 对象，此前 `span[0]/span[1]` 索引恒 `undefined` → 所有 expr 守卫指纹都是 `expr@undefined:undefined` —— 同端点两条**不同的**合法守卫（`x > 1` / `x < 0`，Vigil 惯用法同向多守卫）被 G-8 误杀。改为**表达式结构指纹** `exprFingerprint`（位置无关递归序列化）：同结构 ≡ 复制粘贴（G-8 仍拦截），不同条件 ≡ 合法并行边（不误报）。
- [x] **dhv（Rust）edge guard expr 形态解析**（hsl.pest）：`edge_guard = { pattern | expression }` 的 PEG 有序选择里，pattern 对 `x > 1` 只消费绑定模式 `x` 即成功提交（PEG 不回溯），残留 `> 1` 撞 `edge_attrs? ~ ";"` → E0001 —— `>` `<` `==` `!=` `&&` 全部中招，而 dhv-ts 同源码正常。修复：pattern 分支加负向前瞻 `guard_continues`。回归：`parse/edge_expr_guard_operators.hsl`。
- [x] **下标切片语法 `v[i..j]`**（parser.ts）：值语境 range 在下标语境抢先吸收 `1..3`，postfix 的 slice 分支成死代码 → 解析为 `v[range(1,3)]` → interp 把 range 对象 `Number()` 成 NaN，NaN 绕过越界检查静默返回 `undefined`（下游报误导性「unit 没有方法 len」）。与 dhv（pest 先试 slice）语义分歧。修复：下标语境专用 `parseExprNoRange()`，`[i]` / `[i..j]` / `[i..]` / `[i..=j]` / `[..j]` 全形态可用。
- [x] **复合赋值算术对齐**（interp.ts）：`evalCompound` 的 `%` 缺除零检查（`x %= 0` 静默 NaN）与 bigint 分支；`*` `/` 缺 bigint 分支。全部对齐 `evalBinary` 口径（运行期干净 `HRuntimeError`）。
- [x] **fn/graph body 内 block 资源块**（parser.ts）：`ITEM_KWS` 缺 `'block'` → 顶层合法、函数体内非法的不对称。补齐后与 static 同权。
- [x] **`\x` 转义十六进制校验**（lexer.ts）：`'\xZi'` → `fromCharCode(NaN)` = NUL 字符**静默入值**。对齐 `\u` 的严格口径（2 位十六进制）。
